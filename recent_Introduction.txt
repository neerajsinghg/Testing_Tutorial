Answer: What is your Automation Framework?
In my current project, I have developed a Hybrid Test Automation Framework mainly using 
Java with Selenium for web automation.
The framework is designed to be scalable, maintainable, and reusable so that 
test cases can be easily expanded as the application grows.

Framework Design
The framework follows the Page Object Model (POM) design pattern, where all the web element locators and 
page actions are maintained in separate page classes, 
while the test logic is written in test classes. This separation improves maintainability and readability.

Framework Components
The framework includes several key components:
1. Page Layer
Contains page classes representing each web page.
Stores element locators and reusable methods.

2. Test Layer
Contains test scripts written using TestNG.
Test cases call methods from page classes.

3. Utilities Layer
Common reusable utilities such as:
WebDriver initialization
Wait utilities
Screenshot capture on failure
Excel or JSON data readers
Config file readers

4. Test Data Layer
Test data is maintained separately using Excel, JSON, or properties files, which supports data-driven testing.

5. Reporting
Test execution reports are generated using Extent Reports / TestNG Reports, which provide 
detailed logs, screenshots, and test results.

6. CI/CD Integration
The framework is integrated with Jenkins pipelines, so tests automatically run during build or deployment stages.

Automation Coverage
Using this framework we automated:
Functional UI testing
Regression testing
Smoke test suites
Cross-browser testing
