# 🧠 Element Related Exceptions in Selenium (with STAR + Handling)

## ⭐ 1. NoSuchElementException

### 🟢 Situation (S)

Element DOM me exist hi nahi karta ya wrong locator use hua.

### 🛠 Task (T)

Element ko reliably locate karna aur failure handle karna.

### ⚙️ Action (A)

* Locator verify karo (id/xpath/css)
* Explicit wait use karo
* Page load wait ensure karo

```java
WebDriverWait wait = new WebDriverWait(driver, Duration.ofSeconds(10));
wait.until(ExpectedConditions.presenceOfElementLocated(By.id("login")));
```

### 🎯 Result (R)

Element stable way me found ho jata hai, flaky failure reduce hota hai.

---

## ⭐ 2. StaleElementReferenceException

### 🟢 Situation

Element DOM se refresh/update hone ke baad reference invalid ho jata hai.

### 🛠 Task

Fresh element reference use karke action perform karna.

### ⚙️ Action

* Re-locate element before use
* Use retry mechanism
* Avoid storing WebElement long time

```java
for(int i=0; i<3; i++){
    try {
        driver.findElement(By.id("btn")).click();
        break;
    } catch (StaleElementReferenceException e) {
        Thread.sleep(1000);
    }
}
```

### 🎯 Result

Test stable ho jata hai dynamic pages pe bhi.

---

## ⭐ 3. ElementNotInteractableException

### 🟢 Situation

Element visible hota hai but interact (click/type) nahi hota.

### 🛠 Task

Ensure element is clickable/interactable.

### ⚙️ Action

* Use wait for clickability
* Scroll into view
* Check overlay/loading

```java
WebElement el = wait.until(ExpectedConditions.elementToBeClickable(By.id("submit")));
el.click();
```

### 🎯 Result

Interaction smoothly work karta hai without failure.

---

## ⭐ 4. ElementClickInterceptedException

### 🟢 Situation

Kisi popup/loader/overlay ne click block kar diya.

### 🛠 Task

Ensure element is clickable without obstruction.

### ⚙️ Action

* Wait for overlay to disappear
* Use JS click (last option)
* Close modal/popups

```java
wait.until(ExpectedConditions.invisibilityOfElementLocated(By.id("loader")));
driver.findElement(By.id("btn")).click();
```

OR fallback:

```java
JavascriptExecutor js = (JavascriptExecutor) driver;
js.executeScript("arguments[0].click();", element);
```

### 🎯 Result

Click successfully execute ho jata hai.

---

## ⭐ 5. ElementNotVisibleException (Legacy / rare now)

### 🟢 Situation

Element DOM me hai but visible nahi hai.

### 🛠 Task

Ensure visibility before action.

### ⚙️ Action

* Use visibilityOfElementLocated

```java
wait.until(ExpectedConditions.visibilityOfElementLocated(By.id("msg")));
```

### 🎯 Result

Only visible elements are interacted with → stable test.

# 🔥 Framework-Level Best Handling Strategy

## ✅ 1. Use Explicit Wait (Must)

* presenceOfElementLocated
* visibilityOfElementLocated
* elementToBeClickable

---

## ✅ 2. Retry Mechanism (for stale & flaky UI)

```java
public void clickWithRetry(By locator) {
    for (int i = 0; i < 3; i++) {
        try {
            driver.findElement(locator).click();
            return;
        } catch (StaleElementReferenceException e) {
        }
    }
}
```

---

## ✅ 3. Page Object Best Practice

👉 Never store WebElement as class variable
👉 Always use By locator

❌ Bad:

```java
WebElement loginBtn;
```

✔ Good:

```java
By loginBtn = By.id("login");
```

👉 “Element-related exceptions in Selenium like NoSuchElement, StaleElementReference, ElementNotInteractable, and ClickIntercepted occur due to timing issues or DOM changes. I handle them using explicit waits, proper locator strategies, retry mechanisms, and sometimes JavaScript executor as a fallback. In my framework, I avoid storing WebElements and prefer By locators with reusable utility methods to make tests stable and less flaky.”
