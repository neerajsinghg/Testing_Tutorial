1. difference between web service and api.
	"API is a general interface that enables communication between two software systems, while a web service is a type of API that uses web protocols such as HTTP or HTTPS for communication. In simple terms, all web services are APIs, but not all APIs are web services."
2. various authorisation token provided by postman.
"Postman supports multiple authorization mechanisms such as No Auth, API Key, Bearer Token, Basic Auth, Digest Auth, OAuth 1.0, OAuth 2.0, AWS Signature, and NTLM. In modern REST API automation, Bearer token and OAuth 2.0 are the most commonly used because they provide secure token-based authentication."
| Authorization Type | Description                   | Token / Credentials Format      | Common Usage            |
| ------------------ | ----------------------------- | ------------------------------- | ----------------------- |
| **No Auth**        | No authentication required    | None                            | Public APIs             |
| **API Key**        | Unique key provided by server | `x-api-key: 12345`              | Third-party APIs        |
| **Bearer Token**   | Token passed in header        | `Authorization: Bearer <token>` | JWT / REST APIs         |
| **Basic Auth**     | Username and password encoded | `Authorization: Basic <base64>` | Legacy APIs             |
| **Digest Auth**    | Hashed username/password      | Auto generated by server        | Secure legacy APIs      |
| **OAuth 1.0**      | Older OAuth authentication    | Consumer Key + Secret           | Old integrations        |
| **OAuth 2.0**      | Token-based secure auth       | Access Token                    | Enterprise APIs         |
| **AWS Signature**  | AWS request signing           | Access Key + Secret Key         | AWS services            |
| **NTLM Auth**      | Windows authentication        | Domain + Username + Password    | Internal corporate APIs |

3. what is basic auth in postman.
	"Basic Auth in Postman is an authentication mechanism where the username and password are combined, Base64 encoded, and sent in the Authorization header. Postman automatically generates this header when we select Basic Auth and provide the credentials."
4. what is query parameter.
	A query parameter is a key-value pair appended to the URL after the question mark symbol to pass additional data such as filtering, searching, pagination, or sorting information to the server."
	https://api.example.com/users?status=active&city=Delhi
5. what are global variable in postman.
	"Global variables in Postman are workspace-level variables that can be accessed by any request or collection. They are mainly used to store reusable values such as base URLs, tokens, and dynamic response data across multiple API requests."
| Variable Name | Value                     |
| ------------- | ------------------------- |
| `base_url`    | `https://api.company.com` |
| `token`       | `abc123xyz`               |
{{base_url}}/users
Authorization: Bearer {{token}}

6. is it possible to use authorization token for multiple time.
	"Yes, an authorization token can usually be used multiple times across different API requests until it expires or is invalidated by the server. In automation frameworks and Postman, we commonly store the token once and reuse it in subsequent requests to avoid repeated login calls."

9. what do u understand by header
	"Header is the metadata part of an HTTP request or response that carries additional information such as authentication, content type, accepted response format, and communication instructions between client and server."
example: -- >
	GET /users HTTP/1.1
	Host: api.company.com
	Authorization: Bearer abc123
	Content-Type: application/json
	Accept: application/json
10. what is pre request script
	"A Pre-request Script in Postman is a JavaScript script that executes before sending an API request. It is mainly used to generate dynamic data, set variables, create authentication tokens, or modify request headers automatically."
	Execution Flow
	Pre-request Script → Request Sent → Response Received → Tests Script
11. what is oAuth2.0.
	OAuth 2.0 is an authorization framework that allows one application to access another application’s resources on behalf of a user without sharing the user's actual username and password.
	User → Login
	Application → Authorization Server
	Authorization Server → Access Token
	Application → API with Token
	API → Response
	"OAuth 2.0 is an industry-standard authorization framework that allows secure access to APIs using access tokens instead of sharing user credentials. It enables applications to access protected resources with controlled permissions and token expiration."

12. 100 test cases to run using postman, how you will do that.
	To execute 100 test cases in Postman, I would create a collection, parameterize the request using variables, maintain test data in CSV or JSON format, and use Collection Runner to execute all iterations automatically. For scalable execution in CI/CD, I would use Newman to run the collection and generate reports."
	Data File → Collection Runner → Request Execution → Validation → Report
13. can we have same name global variable.
	"No, Postman does not support duplicate global variable names in the same global scope. If the same variable name is used again, the new value overwrites the existing one. However, the same variable name can exist in different scopes like global, environment, and collection."
