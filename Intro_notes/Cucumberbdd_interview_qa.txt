1. What is Cucumber, and how does it support BDD?
	Cucumber is a tool used for Behavior Driven Development (BDD). It allows writing test scenarios in plain language using Gherkin syntax, 
	which bridges the communication gap between non-technical stakeholders (business analysts, product owners) and developers.

2. What are the key components of a Cucumber test framework?
 	1. Feature Files – Contains test scenarios written in Gherkin language.
 	2. Step Definitions – Maps the Gherkin steps to executable code.
 	3. Hooks – Pre/post conditions executed before or after test scenarios.
 	4. Runner Class – Manages the execution of the tests and integrates with the test framework.

3. Explain Gherkin syntax and its keywords.
	Gherkin is a simple language for writing test scenarios in a human-readable format. Key Gherkin keywords:
 	- Feature: Defines the functionality being tested.	
 	- Scenario: Represents a specific case under the feature.
 	- Given: Specifies the initial context.
 	- When: Specifies an action.
 	- Then: Specifies the expected outcome.
 	- And/But: Helps chain multiple conditions.

4. How do you manage reusable steps in Cucumber?
 	By using parameterized steps and regex in the Step Definition file, common steps across different scenarios can be reused efficiently. 
	Sharing common logic helps reduce code duplication and makes the test suite more maintainable.

5. What is the role of a Runner class in Cucumber?
	The Runner class is used to trigger the execution of the Cucumber tests. It is annotated with @RunWith(Cucumber.class) 
	and contains configuration options such as the location of feature files, step definitions, reports, and Cucumber options like tags and plugin.

6. How do you handle test data in Cucumber scenarios?
 	Test data can be managed in several ways:
 	1. Data Tables – For passing multiple sets of data to a step.
 	2. Scenario Outline – Allows running the same scenario with different sets of data by specifying examples.
 	3. External files – Using property files, JSON, or Excel sheets for managing complex data inputs.

7. What are Hooks in Cucumber, and how would you use them?
	Hooks are blocks of code that run before or after each scenario, defined using @Before and @After annotations. 
	They are useful for setting up prerequisites (e.g., initializing WebDriver) and performing teardown activities (e.g., closing connections).

8. How would you implement tagging in Cucumber, and why is it useful?
 	Tags in Cucumber are used to categorize scenarios. You can assign tags (e.g., @smoke, @regression) to specific scenarios 
	or feature files. In the Runner class, you can use tags in the Cucumber options to control which tests should be executed, 
	allowing flexibility and test suite management.

9. Explain how Cucumber integrates with Selenium.
	Cucumber integrates with Selenium by using Step Definitions, where Gherkin steps are mapped to Selenium WebDriver code. 
	Cucumber handles the feature file's high-level description of a test, while Selenium executes the browser actions for test automation.

10. What is a Scenario Outline, and how does it differ from a regular Scenario?
	A Scenario Outline is used to execute the same scenario with different sets of data. It uses the 
	Examples keyword to specify the data inputs. A regular Scenario runs only once with a specific set of conditions.

11. What is the difference between Background and Scenario in Cucumber?
 	Background is used to define common steps that should be run before each scenario in a feature file. It allows reusing setup 
	steps across multiple scenarios, reducing redundancy. A Scenario, on the other hand, defines a single test case.

12. How do you handle dependencies between scenarios in Cucumber?
	Cucumber discourages scenario dependencies as scenarios should be independent to ensure test reliability. 
	However, if needed, you can use shared state between steps through global variables or dependency injection frameworks like PicoContainer.

13. How can you generate a Cucumber report, and what are the common reporting plugins?
 	Cucumber provides reporting by using plugins such as json, html, and pretty. In the Runner class, the @CucumberOptions annotation can 
	be configured to generate reports by specifying plugin = {"pretty", "html:target/cucumber-reports"}. Common plugins include Cucumber HTML Report, 
	Cucumber JSON Report, and Extent Reports.

14. How do you handle failed scenarios in Cucumber?
 	1. Rerun failed scenarios using the @CucumberOptions rerun plugin, which generates a file containing the failed scenarios.
 	2. Hooks – You can implement a hook using @After to capture a screenshot or perform a custom action upon test failure.
 	3. Retry Mechanism – A retry mechanism can be added in the framework for handling flaky tests.

15. Can Cucumber be integrated with Continuous Integration tools? How?
	Yes, Cucumber can be integrated with CI tools like Jenkins, GitLab CI, or CircleCI. This is done by creating build jobs 
	that automatically execute Cucumber tests as part of the CI pipeline. Test results and reports can be generated and published within the pipeline

# ✅ Step 2: Page Object Class
Create login page class
```java id="g3ow1d"
import org.openqa.selenium.*;

public class LoginPage {

    WebDriver driver;

    By username = By.id("username");
    By password = By.id("password");
    By loginBtn = By.id("loginBtn");

    public LoginPage(WebDriver driver){
        this.driver = driver;
    }

    public void enterUsername(String user){
        driver.findElement(username).sendKeys(user);
    }

    public void enterPassword(String pass){
        driver.findElement(password).sendKeys(pass);
    }

    public void clickLogin(){
        driver.findElement(loginBtn).click();
    }
}

import io.cucumber.java.en.*;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.chrome.ChromeDriver;

public class LoginSteps {

    WebDriver driver;
    LoginPage loginPage;

    @Given("user launches browser")
    public void user_launches_browser() {
        driver = new ChromeDriver();
        driver.manage().window().maximize();
    }

    @Given("user opens login page")
    public void user_opens_login_page() {
        driver.get("https://example.com/login");
        loginPage = new LoginPage(driver);
    }

    @When("user enters username and password")
    public void user_enters_username_and_password() {
        loginPage.enterUsername("admin");
        loginPage.enterPassword("admin123");
    }

    @When("user clicks login button")
    public void user_clicks_login_button() {
        loginPage.clickLogin();
    }

    @Then("user should see dashboard page")
    public void user_should_see_dashboard_page() {
        String title = driver.getTitle();
        System.out.println("Page title: " + title);
        driver.quit();
    }
}
